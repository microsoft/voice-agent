# Ignite 2026 session data

A snapshot of the public Microsoft Ignite 2026 catalog and the data the planner
generates from it. Every session the page and the Agent use comes from here.

The snapshot was taken on **2026-10-28 at 06:59 UTC** from the official site's
public, sign-in-free catalog endpoints. It contains no attendee list. "People"
means **public speakers** only.

## Files

| File | Content |
| --- | --- |
| [sessions.csv](sessions.csv) | Session list for spreadsheet tools: times, location, speakers, categories and source |
| [sessions.json](sessions.json) | Full session metadata for programs, with instance IDs, nulls, and UTC and Pacific times |
| [speakers.json](speakers.json) | Name, company, title, ID and source from the public speaker directory; no biographies or contact details |
| [agenda.json](agenda.json) | The 15 event-level time blocks shown on the home page (not individual sessions) |
| [sources.json](sources.json) | Retrieval times, official URLs, response hashes and data-quality counts |
| [descriptions.json](descriptions.json) | Official session descriptions as plain text, keyed by this snapshot's `instance_id` |

Generated from the snapshot, and the modules that read it:

| File | Content |
| --- | --- |
| [featured-sessions.json](featured-sessions.json) | Hand-written demo blurbs for 8 featured sessions, merged into the catalog |
| [catalog.json](catalog.json) | The catalog used by the page and the Agent, generated by `../tools/session_catalog.py --build` |
| [catalog.mjs](catalog.mjs) | Server: `catalog.json` plus descriptions as `/catalog.json`; the version includes the descriptions |
| [session-details.mjs](session-details.mjs) | Server: speaker titles and companies by ID as `/session-details.json`, and the speaker list for `find_speaker` |
| [name-search-data.json](name-search-data.json) | Tables for the phonetic name matcher, exported by `../tools/build_name_search_data.py` (independent of the snapshot) |

## What the snapshot holds

| Item | Count |
| --- | ---: |
| Session records | 1,469 |
| Distinct session codes | 1,307 |
| Sessions with fixed start and end times | 1,338 |
| Content without fixed times | 131 (104 pre-recorded, 27 digital labs) |
| Records without a published location | 131 |
| Records without published speaker names | 124 |
| Speaker directory records | 1,590 |
| Distinct speaker IDs | 1,571 |
| Speaker IDs that appear twice | 19 |
| Speaker IDs referenced by sessions but missing from the directory | 19, affecting 26 session records |

The sitemap lists 1,469 session URL entries for 1,307 distinct content URLs,
matching every `session_id` in the catalog. Repeated sessions were not merged
by code.

The duplicate and missing speaker IDs are in the upstream responses. The
snapshot keeps the records as returned: it does not merge people by name or
split `speaker_names_text` on commas to pair names with IDs. Joining a session
to speaker titles by ID must handle missing and duplicate matches.

## Session fields

| Field | Meaning |
| --- | --- |
| `session_code` | Human-facing code such as BRK244; one code can have several instances |
| `session_id` | Official content ID |
| `instance_id` / `time_id` | One scheduled instance; use `instance_id` for an agenda |
| `title` | Official title |
| `start_utc` / `end_utc` | Official UTC times; `null` without a fixed time |
| `start_local` / `end_local` | Converted to the event time zone `America/Los_Angeles`, with the UTC offset |
| `duration_minutes` | The official duration field, not derived |
| `location` | Official venue or room text, not coordinates or directions |
| `speaker_names_text` | Speaker names as published on the session, or `null` |
| `speaker_ids` | Speaker IDs referenced by the session; not all are in the directory |
| `session_type` / `levels` / `topics` | Type, level and topics |
| `delivery_types` / `viewing_options` | In-person or online and recording labels; not live player availability |
| `seating_experience` | Seating category, not remaining seats |
| `source_url` | The official page of the instance |
| `source_last_updated_at` | Upstream update time, not the retrieval time |

The JSON files also carry `snapshot_at`, `event_timezone` and `source_url`. In
the CSV, empty cells are missing values and list fields are joined with
semicolons; prefer the JSON in programs.

Example: BRK244 runs on **2026-11-19, 17:15–18:00 Pacific time**
(`2026-11-20T01:15:00Z`–`2026-11-20T02:00:00Z`) at AMC Metreon, Level 3,
Theater 12. Not every session is at Moscone: KEY01 is at Chase Center.

## Sources

The snapshot was read with plain HTTP requests without account cookies from the
endpoints the official catalog itself uses:

| Source | Use |
| --- | --- |
| [Session catalog](https://ignite.microsoft.com/en-US/sessions) | Public browsing entry point |
| [All sessions](https://ignite.microsoft.com/api/session/all/en-US) | Session facts |
| [All speakers](https://ignite.microsoft.com/api/speaker/all/en-US) | Public speaker data |
| [Sitemap](https://ignite.microsoft.com/sitemap.xml) | Coverage check of session content IDs |
| [Home page](https://ignite.microsoft.com/en-US/home) | Event agenda and time zone |
| [robots.txt](https://ignite.microsoft.com/robots.txt) | Checked before every refresh |

These are the site's own endpoints, not a documented API with stability,
compatibility or usage terms. Check the event's requirements before using them
for continuous synchronization or a public product.

Only factual fields are kept: no full abstracts beyond `descriptions.json`, no
speaker biographies, page configuration, tokens, cookies or attendee data. The
SHA-256 values in `sources.json` are of the raw HTTP responses.

Known differences between sources are kept, not merged: the home page's opening
keynote block is 10:00–12:00 PT while KEY01 itself is 10:00–11:30 PT, and the
partner keynote block is 09:00–10:00 PT while KEY02 is 09:00–10:30 PT.

## Refresh and verify

Requires Python 3.11+ with IANA time zone data and no extra packages. From
`ignite_planner/`:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 tools/refresh_snapshot.py
PYTHONDONTWRITEBYTECODE=1 python3 tools/session_catalog.py --build    # regenerate catalog.json
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
```

The refresh overwrites the session JSON and CSV, `speakers.json`, `agenda.json`
and `sources.json`. Network errors, schema changes, invalid times or a failed
coverage check stop it with an error; the known speaker duplicates and gaps are
printed as warnings and recorded in the quality counts. A new snapshot changes
the catalog version the Agent receives, so the next server start creates a new
Agent.

## Official descriptions

`refresh_snapshot.py` keeps only factual fields. The descriptions are added
separately, without changing session IDs, times or counts:

```bash
python3 tools/add_descriptions.py                   # read the official endpoint
python3 tools/add_descriptions.py --from saved.json  # use a saved response
```

It converts the HTML to plain text and matches by `instance_id`, falling back
to the session code. On 2026-10-30, **1,451 of 1,469 session records** had a
description; the rest, mostly lab variants and table talks no longer in the
catalog, are listed under `without_description`.
